Cómo se construyó el prototipo

Esta guía recorre el proyecto desde el CSV de Champions League hasta las probabilidades que aparecen en pantalla. Está pensada para abrirse junto con la carpeta en Visual Studio Code y explicar cada parte en clase.

La idea en una frase

MomioLab aprende patrones de resultados anteriores de Champions League y estima tres probabilidades: gana el local, empate o gana el visitante.

1 · DatosMarcadores del torneo, en orden de fecha.
2 · VariablesForma reciente y duelos directos previos.
3 · EntrenamientoNaive Bayes o Random Forest, con Python.
4 · PredicciónProbabilidades para Local, Empate y Visitante.
5 · ExplicaciónImportancia de variables y métricas.

Alcance fijo: UEFA Champions League y su antecesora directa, la Copa de Europa. El servidor Python revisa competition y descarta todo lo que no tenga esa etiqueta.

1. Preparar los partidos

La entrega incluye el archivo consolidado champions_matches.csv, con los partidos de Champions ordenados por fecha. No necesitas importar ni preparar otras carpetas para explicar el prototipo.

El servidor Python lee el CSV y vuelve a revisar la etiqueta antes de entrenar; así, una fila de otro torneo no se incorpora por accidente. La página consulta al servidor y muestra el resultado.

competencia | fecha | temporada | local | visitante | goles local | goles visitante
Champions   | ...   | ...       | ...   | ...       | ...         | ...

La cobertura y las limitaciones de las fuentes están en FUENTES.md. El conjunto reciente puede no incluir rondas clasificatorias.

2. Convertir marcadores a variables

Los modelos no comparan nombres de equipos directamente. Primero build_examples convierte en Python la historia previa en 12 números y guarda el resultado final como clase objetivo. Para una victoria local, el objetivo es Local; para un empate, Empate; y para una victoria visitante, Visitante.

GrupoQué mideEjemplo
Forma del localPuntos, goles a favor/en contra, diferencia de goles y proporción de victorias en sus últimos cinco partidos.Promedio de puntos por partido.
Forma del visitanteLas mismas medidas, calculadas para el club visitante.Goles recibidos por partido.
Enfrentamientos directosDiferencia de puntos y goles en hasta cinco duelos anteriores de estos dos clubes.Puntos del local menos puntos del visitante.

Orden temporal: antes de agregar el resultado de una fecha a los historiales, el código calcula las variables de todos los partidos de esa fecha. Así un partido no “ve” el marcador de otro que ocurrió el mismo día.

3. Cómo aprende cada algoritmo

Naive Bayes Gaussiano

En fit_naive_bayes calcula la frecuencia, media y varianza de cada variable dentro de Local, Empate y Visitante.

Para predecir combina la probabilidad previa de cada clase con qué tan compatibles son las variables observadas.

P(clase | variables) ∝ P(clase) × Π P(variable | clase)

Supone que las variables son independientes entre sí, dado el resultado.

Random Forest

fit_random_forest genera 17 árboles internos. Cada uno recibe una muestra con reemplazo y considera un subconjunto de variables por corte.

predict_random_forest promedia las probabilidades de los árboles.

predicción del bosque = promedio de votos

La importancia combina la reducción de Gini de todos sus árboles.

Se usan dos modelos: Naive Bayes y Random Forest. Random Forest contiene árboles de decisión como componentes internos, pero el proyecto ya no ofrece un árbol como tercer modelo independiente. Importancia no significa causa; cada modelo la calcula de forma distinta.

4. Cómo se compara el desempeño

Los ejemplos válidos se mantienen en orden cronológico. El 80% más antiguo sirve para entrenar y el bloque posterior para evaluar; los partidos de una misma fecha no se separan entre bloques. Después, el servidor Python vuelve a entrenar ambos modelos con todos los ejemplos para las predicciones interactivas.

MétricaLectura sencillaDirección deseada
AccuracyProporción de partidos donde la clase con más probabilidad fue la clase real.Más alta
Log lossPenaliza predicciones muy seguras cuando el resultado real tenía poca probabilidad.Más baja
BrierCompara las tres probabilidades estimadas con el resultado observado.Más baja

La evaluación usa resultados pasados; no es una prueba de que los modelos anticipen alineaciones, lesiones o cambios actuales de forma.

6. Qué pasa cuando eliges dos clubes

  1. app.js lee los valores de los selectores de local, visitante y modelo.
  2. upcoming_features, en Python, resume el historial del CSV para esos dos clubes.
  3. predict, desde el paquete models, llama al archivo del algoritmo elegido y devuelve tres probabilidades.
  4. Se ordena la importancia y se explica el cálculo de Naive Bayes o el promedio del bosque.
  5. El momio decimal mostrado es 1 / probabilidad. Es una conversión matemática sin margen comercial.

El historial directo y los últimos resultados se agregan debajo para que puedas contrastar la salida con los datos que conoce el prototipo.

7. Cómo demostrarlo en VS Code

Abre la carpeta MomioLab_Champions_IA en VS Code. Desde una terminal en la raíz puedes iniciar el servidor local o ejecutar una predicción explicada.

python pagina/server.py
# abre http://127.0.0.1:4180

python pagina/cli.py "Real Madrid CF" "FC Bayern München" naiveBayes
python pagina/cli.py "Real Madrid CF" "FC Bayern München" randomForest

El servidor pagina/server.py conecta la interfaz con champions_matches.csv y el paquete models/ en la raíz. Usa la biblioteca estándar de Python, así que no requiere instalar paquetes.

Guion fácil para presentar el boceto

  1. Problema: queremos estimar Local, Empate o Visitante con resultados anteriores de Champions.
  2. Entrada: elige Real Madrid y Bayern, y deja Naive Bayes como primer modelo.
  3. Qué analiza: últimos cinco partidos, goles, puntos y duelos directos previos.
  4. Salida: compara las tres probabilidades; el porcentaje más alto es el resultado estimado por el modelo.
  5. Explicación: muestra las variables que separan el resultado sugerido. Después, cambia a Random Forest para comparar enfoques.

Pulsa Mostrar todo el proyecto para abrir el historial, la tabla de métricas y los siguientes pasos. El modo sencillo solo oculta esos detalles durante la primera explicación; Naive Bayes y Random Forest siguen disponibles.

Qué falta para una siguiente versión

El prototipo aún no conoce alineaciones, lesiones, minutos de los jugadores ni cuotas reales. Para añadir esos factores se necesita una fuente compatible por partido y fecha. Monte Carlo y máxima entropía quedan como extensiones; los dos modelos principales ya funcionan en la entrega actual.

Al presentar el resultado, conviene llamarlo estimación académica basada en historial, no garantía de marcador ni recomendación de apuesta.
