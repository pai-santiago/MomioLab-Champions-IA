Cómo se construyó el prototipo

Esta guía recorre el proyecto desde el CSV de Champions League hasta las probabilidades que aparecen en pantalla. Está pensada para abrirse junto con la carpeta en Visual Studio Code y explicar cada parte en clase.

La idea en una frase

MomioLab aprende patrones de resultados anteriores de Champions League y estima tres probabilidades: gana el local, empate o gana el visitante.

1 · DatosMarcadores del torneo, en orden de fecha.
2 · VariablesForma reciente y duelos directos previos.
3 · EntrenamientoNaive Bayes, Árbol o Random Forest.
4 · PredicciónProbabilidades para Local, Empate y Visitante.
5 · ExplicaciónImportancia, ruta del árbol y métricas.

Alcance fijo: UEFA Champions League y su antecesora directa, la Copa de Europa. La columna competition etiqueta las filas y el dashboard/CLI descarta todo lo que no tenga esa etiqueta.

1. Preparar los partidos

Los archivos originales tienen columnas y formatos distintos. prepare-data.mjs los lee, conserva resultados terminados, convierte marcadores a números, normaliza la fecha y el equipo local/visitante, añade la etiqueta de competición y elimina filas duplicadas.

El resultado es data/champions_matches.csv, que ambos caminos de ejecución usan: la interfaz web y la demostración de terminal. La aplicación vuelve a revisar la etiqueta antes de entrenar; así, una fila de otro torneo no se incorpora por accidente.

competencia | fecha | temporada | local | visitante | goles local | goles visitante
Champions   | ...   | ...       | ...   | ...       | ...         | ...

La cobertura y las limitaciones de las fuentes están en data/SOURCES.md. El conjunto reciente puede no incluir rondas clasificatorias.

2. Convertir marcadores a variables

Los modelos no comparan nombres de equipos directamente. Primero buildExamples convierte la historia previa en 12 números y guarda el resultado final como clase objetivo. Para un partido gana el local, el objetivo es Local; para un empate, Empate; y para una victoria visitante, Visitante.

GrupoQué mideEjemplo
Forma del localPuntos, goles a favor/en contra, diferencia de goles y proporción de victorias en sus últimos cinco partidos.Promedio de puntos por partido.
Forma del visitanteLas mismas medidas, calculadas para el club visitante.Goles recibidos por partido.
Enfrentamientos directosDiferencia de puntos y goles en hasta cinco duelos anteriores de estos dos clubes.Puntos del local menos puntos del visitante.

Orden temporal: antes de agregar el resultado de una fecha a los historiales, el código calcula las variables de todos los partidos de esa fecha. Así un partido no “ve” el marcador de otro que ocurrió el mismo día.

3. Cómo aprende cada algoritmo

Naive Bayes Gaussiano

En fitNaiveBayes calcula la frecuencia, media y varianza de cada variable dentro de Local, Empate y Visitante.

Para predecir combina la probabilidad previa de cada clase con qué tan compatibles son las variables observadas.

P(clase | variables) ∝ P(clase) × Π P(variable | clase)

Supone que las variables son independientes entre sí, dado el resultado.

Árbol de decisión

bestSplit prueba umbrales; gini mide si un grupo mezcla muchos resultados o contiene principalmente una clase.

buildTree crea preguntas y ramas. explainTree devuelve la ruta que siguió un partido.

Gini = 1 − Σ proporción(clase)²

La hoja convierte los conteos de Local/Empate/Visitante en probabilidades.

Random Forest

fitRandomForest genera 17 árboles. Cada uno recibe una muestra con reemplazo y considera un subconjunto de variables por corte.

predictRandomForest promedia las probabilidades de los árboles.

predicción del bosque = promedio de votos

La importancia combina la reducción de Gini de todos sus árboles.

Importancia no significa causa. Las barras describen asociaciones aprendidas por el modelo. La estimación de Naive Bayes se calcula de forma distinta a la importancia Gini de los árboles.

4. Cómo se compara el desempeño

Los ejemplos válidos se mantienen en orden cronológico. El 80% más antiguo sirve para entrenar y el bloque posterior para evaluar; los partidos de una misma fecha no se separan entre bloques. Después, el dashboard vuelve a entrenar cada modelo con todos los ejemplos para su selector interactivo.

MétricaLectura sencillaDirección deseada
AccuracyProporción de partidos donde la clase con más probabilidad fue la clase real.Más alta
Log lossPenaliza predicciones muy seguras cuando el resultado real tenía poca probabilidad.Más baja
BrierCompara las tres probabilidades estimadas con el resultado observado.Más baja

La evaluación usa resultados pasados; no es una prueba de que el modelo pueda anticipar alineaciones, lesiones o cambios de forma actuales.

6. Qué pasa cuando eliges dos clubes

  1. app.js lee los valores de los selectores de local, visitante y modelo.
  2. upcomingFeatures resume el historial que existe en el CSV para esos dos clubes.
  3. predict devuelve tres probabilidades y la interfaz marca la más alta.
  4. Se ordena la importancia de variables y se crea una explicación específica: contribuciones de Naive Bayes, ruta del árbol o resumen del bosque.
  5. El momio decimal mostrado es 1 / probabilidad. Es una conversión matemática sin margen comercial.

El historial directo y los últimos resultados se agregan debajo para que puedas contrastar la salida con los datos que conoce el prototipo.

7. Cómo demostrarlo en VS Code

Abre la carpeta MomioLab_Champions_IA. La app se ejecuta en el servidor local y el ejemplo imprime los pasos del algoritmo en la terminal.

npm start
# abre http://127.0.0.1:4180

npm run demo -- "Real Madrid CF" "FC Bayern München" naiveBayes
npm run demo -- "Real Madrid CF" "FC Bayern München" decisionTree
npm run demo -- "Real Madrid CF" "FC Bayern München" randomForest

En VS Code también puedes abrir Terminal → Ejecutar tarea y elegir el dashboard o la demostración de Naive Bayes. El servidor server.mjs sirve el HTML, CSS, JavaScript, CSV y esta guía.

Guion fácil para presentar el boceto

  1. Problema: queremos estimar Local, Empate o Visitante con resultados anteriores de Champions.
  2. Entrada: elige Real Madrid y Bayern, y deja Naive Bayes como primer modelo.
  3. Qué analiza: últimos cinco partidos, goles, puntos y duelos directos previos.
  4. Salida: compara las tres probabilidades; el porcentaje más alto es el resultado estimado por el modelo.
  5. Explicación: muestra las variables que separan el resultado sugerido. Después, cambia a Árbol o Random Forest para comparar enfoques.

Pulsa Mostrar todo el proyecto para abrir el historial, la tabla de métricas y los siguientes pasos. El modo sencillo solo oculta esos detalles durante la primera explicación; los tres algoritmos siguen funcionando.

Qué falta para una siguiente versión

El prototipo aún no conoce alineaciones, lesiones, minutos de los jugadores ni cuotas reales. Para añadir esos factores se necesita una fuente compatible por partido y fecha. Monte Carlo y máxima entropía quedan como extensiones; los tres modelos principales ya funcionan en la entrega actual.

Al presentar el resultado, conviene llamarlo estimación académica basada en historial, no garantía de marcador ni recomendación de apuesta.
